# 内容理解与召回参考

## 建索引

先问“以后可能因什么问题需要这份材料”，再决定记录什么。对每个知识单元按材料本身选择信息，不强制所有条目填满模板：

| 维度 | 可记录的内容 |
|---|---|
| 对象 | 项目、功能、实验、问题、名称、标识及来源中出现的别名 |
| 事件 | 做了什么、为什么、使用什么方法或条件 |
| 结果 | 发现、决策、异常或未完成事项及其范围 |
| 定位 | 路径、关键成员、章节／字段／行号，便于打开原文 |
| 使用限制 | 旧版本、否决、失败、未经验证、仅在特定条件有效等 |

文本看结构化标题与关键段落；日志看起止、错误、结果及邻近上下文；JSON／表格先看结构和关键字段；PDF／Office／图像只在工具可用且确有检索需要时提取。空文件或无法解析的材料按文件与已知元数据索引，明确限制；不把文件名伪装成内容摘要。对极长或高度异质材料，按章节、条目或批次建少量子条目；按需展开，不将原文复制进索引。

关键词和简注不是另一套事实源。陈述结果要能回到原文；未证实的因果关系标为未知。聚合多个文件时，只对确有共同范围的内容建立汇总，例外单独指出。需要同义词时优先用文件及权威入口已有称谓；推测的检索扩展可用于查询，不作为已证实的别名写入索引。

## 分阶段找回

1. 抽取问题中的对象、动作、约束、结果与时间；不要只匹配完整句子。用户提供的确切文件名／编号优先。
2. 对索引分别搜索有区分度的词和可信别名；交叉检查候选的主题、时间、对象和状态，不因单词出现就断言回答成立。多结果按匹配与适用性筛选，不隐瞒冲突。
3. 无匹配或候选不足时，按主题或批次检索；对选定包检查成员名称，再搜索可读正文。跨语言、换说法或未知别名可能需要扩大范围。二进制、加密和提取失败的材料须作为覆盖缺口报告。
4. 打开候选原文的必要上下文，区分文件实际内容、历史观察和当前事实。路径失效时先核对索引与文件状态；不静默替换为看起来相近的其他文件。

## 验证与边界

完成索引后，从不同材料提出若干检索问题：已知名称、描述性问法、原因／结果、有否定或版本限制的问题，以及无答案的问题。对每个问题记录：候选是否覆盖已知目标、无关候选是否干扰、原文能否支撑回答、有效性和证据位置是否正确。先完成索引，再拟题；不针对问题临时手写答案充当索引。

样本应包含从已索引内容能回答的问题，也包含需要分阶段搜索或不得确定回答的问题。至少一次覆盖索引未命中后扩大搜索；如果格式不能解析或内容过大而未检查，明确说明覆盖范围。样本是回归检查，不是独立评估或全库召回率。
